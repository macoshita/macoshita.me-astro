結構経ってしまったが ISUCON 2026 の参加記録を公開する。\
事前準備はほぼなし、前日に ISUCON 14 の問題を AI に解かせて優勝者のスコアを超えるところまで確認して「これどういう戦いになるんだ……？」という感じで挑んだ。\
が、終わってみると、「いつもの ISUCON だった」という気持ちと「新しい ISUCON が始まった」という気持ちが入り混じる、とてもいい体験をさせてもらえた大会だった。運営の方々ありがとうございました。

結果としては、どうにか 10 万点を超えて 63 位という結果。全体で見た時は割と上の方ではあったが、弊社の別チームが 7 位となっていて、そこに負けたのがくやしい！\
そちらのチームが書いた以下のブログのほうがこのブログよりもしっかり書かれているのでぜひ読んでほしい。\
[ISUCON2026 参加記（新社屋2 / 最終 7 位・436,993 点）](https://zenn.dev/jigjp_engineer/articles/c687d725247534)

## 1. 準備(〜10:25)

- 例年通り webapp 以下を GitHub にすべて投入。
- 例年と違うのは manual.md にレギュレーションを転載してコミットしたことと、 `AGENTS.md` を削除したこと。
- `AGENTS.md` そのままにしとくと「本番環境だから触らない」とか色々書かれてたので良くないと判断した。
- 💬「これから isucon を始めます！ とりあえず軽く中身見てみてください」

## 2. 初期チューニング(10:32〜11:26)|6,817 → 約 25,000

- 💬 `/goal`「これから 1 時間、ベンチマークの結果がなるべく高くなるように、manual.md と README の中身を確認したうえで、改善を進めてください。コミットするときにスコアの数字をコミットログに入れてください。」
  - とりあえず 1 台だけひたすら改善を回し続けるマシンを用意しとこう、という方針でこうした。3 人でどううまく分担するかがあまり整理できていない段階。
- 🤖 インデックスの追加、画像署名のキャッシュ、PostgreSQL 設定の調整
- 🤖 ロック競合を解消し、閲覧者情報・投稿・コメント・RealMoji などで DB への往復を削減
- 🤖 DB 接続を使い回すようにし、取得処理の一部を並列化
- 🤖 GC の頻度を下げる設定(GOGC=200)を試したが、効果は小さめ
- 🤖 画像の寸法超過を、ヘッダーだけで判定するように変更
  - このへんまでは例年通り？　例年ならこれで 4 時間くらい溶かしてる気はするので時代は変わったなぁという感じ
- 💬 「画像を DB に入れているのはボトルネックの原因になっていないでしょうか？」「europe や america が asia2 の DB を見に行く構成ですが、そもそもこれをなんとかできないでしょうか？」「DB 接続の TLS 無効化、これそんなに効きます？」
  - コミットの内容を読んでて疑問に思ったことを聞いてみてる。なんとなくこのままだと思い切った改善は行われなさそうな気がし始めている段階。
